# Retrospectives

This folder contains project, epic, or release retrospectives.

Retrospectives preserve learning and prevent the same mistake from being rediscovered by future agents.

## File naming

Use stable names:

- EPIC-001-retrospective.md
- release-YYYY-MM-DD-retrospective.md

## Retrospective rules

A retrospective should include:

- delivered scope
- original goals
- actual outcome
- what worked well
- what did not work well
- blockers
- decisions
- lessons by agent area
- documentation updates required
- follow-up tasks

## Closure rule

Large projects or epics should not be closed without a retrospective when meaningful lessons, deviations, or operational changes occurred.
